# Удалённый рабочий стол: xrdp

Оба профиля Git включают xrdp с отдельным Xorg-сеансом BSPWM.
Это новый рабочий стол, а не трансляция открытого экрана ноутбука.

## Подключение из Windows

1. На ноутбуке завершите локальный сеанс того пользователя, под которым будете входить по RDP: Power → Logout. Блокировки недостаточно.
2. В Windows нажмите Win+R, выполните `mstsc`.
3. Укажите IP компьютера и порт 3389, в формате `IP_КОМПЬЮТЕРА:3389`.
4. При первом подключении клиент покажет предупреждение о самоподписанном сертификате сервера.
5. В окне xrdp выберите **Xorg**, введите имя обычного пользователя и его пароль. На исходном ноутбуке это `criket`; SSH-ключ для RDP не используется.
6. Для сочетаний Super выберите в настройках клиента «Локальные ресурсы → Клавиатура → На удалённом компьютере».

Если локальный графический сеанс этого пользователя ещё открыт, появится сообщение с просьбой сначала выйти из него. Его панель и окна не завершаются автоматически.
После входа доступны оформление BSPWM, меню Super+D и те же рабочие столы/горячие клавиши.
Проброс звука в RDP не включён; локальный звук PipeWire остаётся в прежней конфигурации.

Закрытие окна mstsc отключает клиент. Для завершения удалённого сеанса выберите Power → Logout внутри него.
Перед возвращением к локальной работе того же пользователя завершите RDP-сеанс, чтобы не оставлять два графических сеанса одновременно.
Hiddify запускается на локальном X11-дисплее :0; управлять им из RDP не предусмотрено. Системный VPN v2rayA настраивается через локальный web-интерфейс.

## Параметры на других ПК

Модуль: `services/rdp.nix`. Разрешён пользователь, выбранный установщиком.
В `/etc/nixos/local/private.nix` можно отключить RDP или изменить порт:

```nix
{ ... }: {
  services.bspwmRdp.enable = false;
  # services.bspwmRdp.port = 3390;
  # services.bspwmRdp.openFirewall = false;
}
```

Для дополнительных существующих обычных пользователей добавьте их имена в `services.bspwmRdp.allowedUsers`.
Root, пустой пароль и пользователи вне группы `rdp-users` не допускаются. SSH-пользователь не получает RDP автоматически.
Порт 3389 открывается локальным firewall. Для доступа из интернета используйте VPN или SSH-туннель вместо проброса RDP-порта на роутере.

Через SSH-туннель (вместо прямого подключения):

```sh
ssh -p 5555 -N -L 13389:127.0.0.1:3389 youruser@IP
```

В mstsc укажите `127.0.0.1:13389`.

## Диагностика

```sh
systemctl status xrdp xrdp-sesman
sudo ss -ltnp | grep 3389
journalctl -u xrdp -u xrdp-sesman -b
```

Развёртывание из Git: `sudo nixos-rebuild switch --flake path:/etc/nixos#current`.
На исходном ноутбуке пока используется `sudo nixos-rebuild switch -I nixos-config=/etc/nixos/configuration.nix`.
Резервная копия до добавления xrdp: `~/nix-backups/xrdp-before-20261018/`.
Сведения о сеансах systemd: [документация xrdp](https://github.com/neutrinolabs/xrdp/wiki/Tips-and-FAQ#why-cant-i-log-the-same-user-on-on-the-graphical-console-and-over-xrdp-at-the-same-time).
